Three contract bugs in one schema, each from Jackson 2 introspecting the domain
record the way swagger-core does:
- amount is a number: a generated client would parse it as a double, the exact
  loss section 2 measured (9999999999999999.99 -> 10000000000000000).
- currency is java.util.Currency's bean properties (displayName, symbol, ...),
  not the ISO code the API actually sends.
- negative, from Money.isNegative(), is advertised as a field.
None of this is what LedgerJacksonModule writes: the served contract and the
wire disagreed. The POSTs were documented as 200, and no error response at all.

The same success request under MockMvc (@WebMvcTest), from the first draft of
this test, before it moved to a real server:
  interceptor   postHandle, response committed false
  filter      < status 200, committed false
MockMvc buffers the whole response, so a test there would suggest postHandle
can still add a header. On Tomcat the @ResponseBody is already written and
flushed when postHandle runs.

The order, as observed:

  TraceIdFilter ─┐ recording filter ─┐ DispatcherServlet
                 │                   │   handler lookup ── 405/415 end here: no interceptor, no aspect
                 │                   │   interceptor.preHandle(handler)
                 │                   │   argument binding + @Valid ── 400 ends here: no aspect
                 │                   │   aspect around the controller method (sees args, result, exception)
                 │                   │   message converter writes the body   (response committed)
                 │                   │   interceptor.postHandle               (skipped if the handler threw)
                 │                   │   @RestControllerAdvice resolves an exception into a ProblemDetail
                 │                   │   interceptor.afterCompletion(ex = null once the advice resolved it)
                 │                   └ recording filter exits
                 └ TraceIdFilter exits, MDC cleared

What this demonstrates
-----------------------

The other two rules (domain-no-adapter-dependency, adapter-web-no-
persistence-dependency) were not separately reproduced here: both are
enforced structurally by Maven already (domain and adapter-web do not
declare adapter/adapter-persistence as dependencies, so a violating import
would not compile in the first place), so an ArchUnit violation for them is
only reachable once a later stage adds those modules' first real classes and
genuinely wires a wrong dependency between them — which is exactly why those
two rules stay vacuous today rather than demonstrable now. The
@Transactional rule is the only one of the three checkable without a
compile-time module boundary already doing the same job, since annotating a
class is legal anywhere in the tree right now.
